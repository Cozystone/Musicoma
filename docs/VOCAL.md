# Musicoma 보컬 설계 (2026-10-15, 본인과 합의)

## 원칙
- 곡·반주·악기는 연주로 만든다(파형 생성 없음). **보컬만 예외**로 AI 가 노래를 생성한다.
- **실존 인물 목소리 복제 금지**(가수·유명인, 테스트 포함). 목소리는 본인 것, 계약으로 권리를 받은 것, 또는 상업 이용이 명시된 것만.
- 판매 제품에 들어가는 모델·목소리는 **코드·가중치·학습 데이터 세 가지 모두** 상업 이용 가능해야 한다.

## 사용자 흐름 (본인 제안 계층 구조)
```
1 비트(연주)           Musicoma 가 곡을 짓는다
2 목소리 고르기         사용자가 '승인된 목소리' 중 선택 · 또는 자기 목소리 등록(녹음 → 음색 프로필)
3 기본형 보컬           비트의 키·코드·구조에 맞춰 멜로디 초안 + '라라라' 가이드 보컬 자동 생성
4 가사 넣기             가사를 넣으면 음절을 멜로디에 배분 → 같은 목소리로 다시 부름
5 다듬기                음 하나·음절 하나 단위로 음정·길이·세기·숨·비브라토 수정 (피아노롤과 같은 방식)
6 믹스                  보컬 체인(EQ·컴프·디에서·리버브·더블링) — 기존 Musicoma 믹스 계층
```
모든 단계는 데이터(멜로디 MIDI + 음절 + 표현 곡선)로 남는다 → 노래도 '편집 가능한 악보'에서 나온다.

## 결정
- **1단계(지금)**: SoulX-Singer 로 흐름 전체(2~5단계)를 먼저 완성하고, 목소리는 **본인 녹음**으로 시험. 이전 '보컬로이드 같음'의 원인(예시 목소리·높은 음역·합성 곡선) 개선: 본인 음역에 맞춘 멜로디, 악보 모드(B) 기본, 음역 자동 이동.
- **2단계(판매용)**: DiffSinger 계열로 **Musicoma Voice** 를 직접 학습. 데이터 = 계약 가수 녹음(목소리당 2~4시간, 한·영, 상업·학습·배포 권리 양도 계약). 기본 목소리 4종(남·여 × 부드러움·힘).
- **3단계(커스터마이징)**: 사용자 자기 목소리 등록 — 녹음 대본(약 30~60분) 화면 + 로컬 학습(5080 기준 수 시간). 음색 손잡이: 숨소리·긴장도·밝기(포먼트)·비브라토 깊이/속도·음 사이 미끄러짐.

## 랩 보컬 (10-15 본인: "랩은 AI 보이스, 본인 목소리를 학습시켜서")
흐름 = **플로우(박자 격자) → 말소리 합성 → 음절을 격자에 맞춰 늘이고 줄이기 → 본인 음색으로 변환 → 믹스**

| 단계 | 후보 | 라이선스(확인한 것) |
|---|---|---|
| 가사·플로우 | Claude 가 가사 + 음절별 박자 격자(16분·3연·당김)를 씀 | 우리 코드 |
| 말소리(영어) | Kokoro TTS | Apache-2.0 (코드·가중치) — 목소리 복제 불가, 기본 목소리만 |
| 말소리(한국어 포함) | GPT-SoVITS (1분 데이터로 목소리 학습, 한·영·일·중) | 코드 MIT · **사전학습 가중치 라이선스 미표기 → 확인 전 판매 보류** |
| 박자 맞추기 | 강제 정렬(음절 경계) + 음절별 타임스트레치 | 우리 코드(Rubber Band 대신 자체 구현 예정) |
| 본인 음색 변환 | **Applio (RVC 계열)** — 10분 녹음으로 학습 | **코드·가중치 MIT, 공식 모델은 VCTK 공개 데이터로 학습**, 상업 이용 허용(이용 약관 준수) |
| 노래(멜로디 있는 훅) | SoulX-Singer (악보 입력) | Apache-2.0 (코드·가중치), 사전학습 데이터 출처는 확인 필요 |

- 피할 것: so-vits-svc 공식(AGPL-3.0), 그 사전학습 모델(CC BY-NC-SA, 비상업), Seed-VC(GPL 계열 — 확인 필요), 커뮤니티 RVC 목소리 모델(대부분 비상업·초상권 문제).
- 1차 조합(판매 가능 쪽): **Kokoro(영어 말소리) + 우리 정렬 + Applio(본인 음색)**. 한국어 랩은 GPT-SoVITS 가중치 라이선스 확인 후, 안 되면 한국어 TTS 를 우리 녹음으로 직접 학습.

## 목소리 '생성' (10-15 본인: "고르거나 커스터마이징이 아니라 매번 새롭게 생성으로")
- 엔진 **VoxCPM2 Voice Design** (OpenBMB, 코드·가중치 Apache-2.0, 30개 언어·한국어, 48kHz, ~8GB) — 설명 한 줄로 새 목소리.
  `third_party/voxcpm/.venv` 에 따로 설치(메인 환경과 분리).
- 목소리 = **설명 + 시드**. 같은 설명·같은 시드 = 같은 사람, 시드만 바꾸면 같은 느낌의 다른 사람. `voice_design.design()`
- 첫 샘플(design.wav)을 기준 음색으로 이후 모든 문장을 같은 사람이 말함(Controllable Cloning).
- **랩**: `voice_design.rap()` = 줄마다 생성 → 단어 시작(faster-whisper) → 16분 격자로 lock 만큼 당겨 구간별 늘이기(자체 WSOLA). 
  시험(86BPM, 4줄): 받아쓰기 100% 일치, 격자 오차 평균 27ms.
- **노래**: 생성 목소리를 SoulX 프롬프트로 등록(`voice.add_voice_aligned`, NeMo 없이 우리 정렬) → 악보대로 부름.
  빠른 음에서 발음이 뭉개짐 → 지금은 '샘플 레코드 속 보컬'(배속·비닐로 칩멍크화)에 쓴다.
- 미세조정 = `voice_character`(WORLD 손잡이: 숨·거칠기·포먼트·나이·밝기). 
- MCP: `voice_design`, `rap`, `voice_character`. 설계서 파트 `"rap": {...}` / `"vocal": {...}`. 한 곡에 여러 목소리·듀엣 = 트랙/파트를 나눠 각각 다른 voice.

## 10-15 오후 — 노래 품질 개선(측정)
받아쓰기 오류율(낮을수록 또렷)로 비교. 노래 = 생성 목소리 gen-singer-b.

| 방식 | 조건 | 오류율 |
|---|---|---|
| 옛 방식(SVS melody 모드, 단어 단위) | 영어 16분음 100BPM, 3시드 | 0.63 |
| SVS score 모드 + 음절 나누기(`ev- ery`) | 같은 조건 | **0.00** |
| + 자음 앞당기기(preroll) | 같은 조건 | 0.17 → 기본 끔 |
| 한국어 SVC 경로(말소리 가이드 → 음표 정렬 → SoulX-SVC, cfg 5, 3테이크 중 최선) | 8분음 86BPM | **0.14** (도시의→도시에 = 같은 발음, 불→물 1글자) |
| 한국어 16분음(0.17초/음절) | 86BPM | 가이드부터 0.33 — 너무 빠름. 한국어는 8분음 이상 권장 |

- 원인(조사): SoulX melody 모드는 가사를 바꾸면 발음이 망가짐(메인테이너 이슈 #33) · 영어 단어 음소를 프레임에 반복 배치해서 짧은 음표면 음소가 통째로 빠짐 · 하이픈 음절이 쉼으로 바뀜.
- 결정: 영어 = SVS score + 음절(`voice.sing`), 한국어·그 밖 = SVC 경로(`sing_svc`), 테이크 3개 중 받아쓰기로 고름(녹음실 방식). 설계서 `vocal` 파트는 가사에 한글이 있으면 자동으로 SVC.
- 제외(라이선스): Vevo2(CC-BY-NC-ND), YingMusic v1(NC), DiffSinger 커뮤니티 보코더(NC-SA), TechSinger(불명).

## 10-15 저녁 — 반주를 '듣고' 부르는 보컬(ACE-Step 1.5 XL-base Lego) — 본인 결정
본인: "비트를 주면 AI 가 그 위에 보이스를 올려야지, 우리가 단문을 잡고 늘리는 게 아니라." TTS+박자 정렬 랩은 "중얼거림·나레이션"으로 불합격.
- 엔진: ACE-Step 1.5 `acestep-v15-xl-base`, `task_type="lego"`, 트랙 vocals (코드·가중치 MIT). `third_party/ace-step-15`(별도 venv), 다리 `musicoma/bridges/ace_lego.py`.
  16GB: int8 양자화 + CPU 오프로드 + 비트를 구간 ±10초(최대 44초)로 잘라서 → 생성 한 번 8초.
- 출력 = 그 구간을 비트까지 새로 그린 믹스 → demucs 로 보컬만 → **원래 비트** 위치에 놓는다(우리 비트는 그대로).
- 테이크 고르기(`musicoma/lego.py`): 받아쓰기 오류율 + 첫 구간 목소리와의 MFCC 유사도. 다음 구간엔 고른 보컬을 참조 음성으로(같은 사람 유지 — 유사도 0.91 → 0.99).
- 측정
  | 경우 | 성공률 | 박자(±20ms 안 / 흔들림) |
  |---|---|---|
  | 칸예 붐뱁 + 남자 랩 | 8개 중 2 (오류율 0.10~0.12) | 25% / ±47ms (Through The Wire 실측 19% / ±48ms) |
  | 같은 비트, 샘플 보컬 제거 | 4개 중 2 | 19% / ±48ms — 문맥 보컬은 필요 없음 |
  | 시티팝 '꽉 찬' 반주 + 여성 노래 | 0 (보컬 -45~-60dB, 거의 무음) — 캡션·언어·참조·cover 모두 실패 |
  | 같은 반주를 드럼·베이스·CP80 만 남긴 가이드 | 16개 중 3개가 오류율 ≤ 0.34 (최고 0.27) |
- 규칙: ① 보컬 생성용 반주는 덜어서(가이드) ② 노래는 랩보다 어려움 → 구간당 16~20 테이크 ③ vocal_language 명시 ④ cover 모드는 박자가 우리 반주와 안 맞음(타격 상관 ~0) → 쓰지 않음.
- 추가(006 「Last Exit」): 10마디(2절6+프리4)를 한 창으로 주면 42테이크 모두 실패 → 2절·프리로 나누자 첫 16테이크에서 성공(0.13 / 0.19). **보컬 생성 창은 짧게(8마디 이하)**. 참조 음성 경로는 절대경로로(상대경로면 ACE 가 못 읽고 조용히 실패).
- 추가(006 v2, 10-15 밤) — 보컬 생성 규칙 확정(측정):
  1. **가이드는 '가이드 전용 악기'로 트랙별 렌더를 그냥 더한 것**(`lego.render_guide`, `GUIDE_PALETTE` = live_room 드럼·피크 베이스·CP80). 곡의 실제 악기(SM Drums·핑거 베이스·FM 피아노)로 만든 가이드나, 마스터 체인을 거친 전체 렌더 가이드는 8/8 실패.
  2. **가이드 멜로디는 생성 구간 안에만**. 앞뒤 문맥에 멜로디 악기가 들리면 모델이 '악기가 노래하는 곡'으로 보고 보컬을 안 얹는다(8/8 실패 → 5/8 성공).
  3. **구간별 조성 전달**(전조 구간에 원래 조성을 주면 보컬이 옛 조로 부름 — '뒤에서 음정 틀어짐'의 원인).
  4. **통과한 테이크만 목소리 참조로**(실패작이 참조가 되면 뒤가 전부 무음).
  5. 이음새: 구간 [시작-0.15초, 끝] 만 쓰고 페이드(겹치면 '여러 목소리'로 들림).
  6. 같은 가사·코드가 반복되는 구간(프리코러스)은 성공 테이크를 재사용해도 된다.
  결과: 7구간 중 6구간 오류율 0~0.2, 목소리 유사도 0.99.

## 10-15 밤 — 속도(본인: "음악 만드는 속도를 올릴 수는 없나? 보컬 때문인가?")
측정(Coffee Rings 랩 7구간): 구간마다 모델 로드 23초 + 10테이크 × 생성 10초 + 테이크마다 demucs 프로세스 새로 띄우기·받아쓰기 5.3초 = 구간당 약 3분 → **보컬 22분 47초**.
고친 것:
1. **모델 상주** — `musicoma/bridges/ace_lego.py --serve`, `lego.server()`. 한 곡(한 파이썬 프로세스) 동안 ACE-Step 을 한 번만 올린다.
2. **demucs 를 프로세스 안에서**(`lego.vocals_only`, 모델 캐시) — 테이크당 2.8초 → 0.2초.
3. **생성과 채점을 겹친다** — 테이크 n 을 채점하는 동안 n+1 을 생성.
4. **조기 멈춤** — 통과(오류율 ≤ pass_wer · 조성 ≥ min_key_fit · 목소리 유사도 ≥ 0.95) 테이크가 `enough=3` 개면 그 구간은 끝. `takes` 는 최대치.
5. 가이드 캐시 — 드럼·베이스·건반 파트가 같으면 가이드 렌더 생략(`guide_stems.sha1`).
6. 밸런스 2회차부터 **움직인 트랙만** 다시 렌더(`Song.render_stems(only=)`).
7. 곡 스크립트의 `all` 은 반주만 따로 짓지 않는다(가이드 → 보컬 → 최종 빌드).
결과: 보컬 **22분 47초 → 10분 11초**(70 → 49 테이크). 고른 테이크 오류율 0~0.16 · 유사도 0.988~0.997 — 이전(0~0.14 · 0.978~0.99)과 동급 이상.
남은 바닥: 생성 자체가 테이크당 10초(XL-base 50스텝, int8+오프로드). 더 줄이려면 스텝 수 실험 또는 반주 빌드와 보컬 생성을 동시에(엔진은 보컬 동안 놀고 있음).
